# Passwordless proofs are Token kinds

Magic-link and email-OTP sign-in use new `TokenKind` values in the existing Token store, rather than adding a separate verification table as Better Auth does. Only each proof's digest is stored, so the raw code or link token exists only in the email. Magic links are issued through `token.Service.IssueWithData`; a six-digit OTP is written directly with `TokenStore.CreateToken` and a digest of `email + ":" + code`, because the user holds the code rather than an opaque token. Reusing the Token store keeps Signet secure by default, gives both factors one atomic single-use/expiry implementation, and leaves the `Store` contract unchanged for Phase 2's secondary-storage adapter.

We considered a verification table whose value carries a failed-attempt counter (`otp:attempts`, Better Auth's model). It would give durable attempt counting, but it needs new Store methods and a second consume path, and secondary storage would have to cover it too. Signet instead limits failed guesses with the existing `RateLimiter`, so the limiter's state — not the Token — tracks attempts. A consequence is that restarting a limiter resets those counters, and a User created by a proof has no credential Account until they set a password.
