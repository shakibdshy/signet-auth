If a capability is not listed under **Shipped today**, it is not available in this

This page describes the `v1.0.0-beta.2` release line. See the
[changelog](https://github.com/shakibdshy/signet-auth/blob/main/CHANGELOG.md) for release notes.

## Shipped today

- **Email/password auth** — sign-up, sign-in, sign-out, rehash, anti-enumeration. See [Quickstart](/docs/quickstart) and [Security](/docs/security).
- **Sessions** — hashed tokens, idle/absolute deadlines, freshness checks, list/revoke, secure cookies and CSRF. See [Sessions and cookies](/docs/sessions).
- **Email verification, email change, password reset/change and verified account deletion** — single-use Tokens, templates and full revocation. See [Verification and reset](/docs/verification-and-reset).
- **OAuth sign-in** — [Google](/docs/google), [GitHub](/docs/github) and [generic OIDC](/docs/oidc) adapters, PKCE, encrypted state, verified-only linking and custom providers. See [OAuth sign-in](/docs/oauth).
- **JWT mode** — Access/Refresh Tokens, rotation and replay containment. See [JWT mode](/docs/jwt).
- **Passwordless sign-in** — magic links and six-digit email OTPs, digest-only proofs, verified email and Session issuance. See [Passwordless sign-in](/docs/passwordless).
- **Session and token hardening** — opt-in Session cache, CSRF/JWT key rings, opt-in JWKS handler and validated redirect patterns. See [Sessions](/docs/sessions), [JWT mode](/docs/jwt) and [Security](/docs/security).
- **Username, account management and Second factor** — username sign-in, safe account listing/unlinking, TOTP with Backup codes and Two-factor challenges. See [Username and accounts](/docs/accounts) and [Second factor](/docs/two-factor).
- **Storage adapters** — [SQLite](/docs/sqlite) and [PostgreSQL](/docs/postgres) with explicit migrations and a conformance suite. See [Storage](/docs/storage).
- **Mailers and templates** — console and SMTP adapters, overridable templates. See [Mail](/docs/mail).
- **Developer surface** — typed Go API, HTTP endpoints, generated OpenAPI contract, typed TypeScript client, docs handler and Fumadocs site. Per-endpoint rate-limit rules and trusted-proxy keys are configurable. See [Go API](/docs/go-api), [HTTP API](/docs/http-api), [Configuration](/docs/configuration), [Tooling](/docs/tooling).
- **Security controls** — Argon2id with bounded parsing, rate-limiting interface, redacted hooks, structured events, and opt-in [defensive controls](/docs/defensive-controls). See [Security](/docs/security).
- **Authorization and management** — application-managed [roles and permissions](/docs/authorization), [API keys](/docs/api-keys), [organizations](/docs/organizations) and guarded [admin management](/docs/admin-management).
- **Passkeys** — opt-in [WebAuthn first factor](/docs/passkeys) with discoverable sign-in and an application-owned credential store.
- **Automatic sign-in** — opt-in Session issuance after [Sign-up or email verification](/docs/verification-and-reset).
- **Authorization server** — opt-in [OAuth token issuance](/docs/authorization-server) with PKCE, refresh rotation and device authorization.
- **Organization SSO** — opt-in per-organization [OIDC SSO](/docs/organization-sso) with verified domains and just-in-time provisioning.
- **SAML SSO** — opt-in [SAML 2.0 Web SSO](/docs/saml) with signed assertions and the shared provisioning path.
- **SCIM provisioning** — opt-in [directory provisioning](/docs/scim) for Users and Groups with role projection.
- **Account controls** — profile updates, server-side password checks, window-aware rate limits and [queryable audit events](/docs/account-controls).
- **React session hooks** — optional `useSession()` package in [`client/react`](https://github.com/shakibdshy/signet-auth/tree/main/client/react).

## Not implemented yet

All six roadmap phases are shipped. The items below are known limitations and capabilities that remain researched but not implemented.

### Known limitations

- Sign-up writes the User and its credential Account in two Store calls; there is no
  transaction across them. A best-effort delete removes the User if the second call fails.
- Rate limits use a boolean `RateLimiter` interface with per-endpoint rules and opt-in
  trusted-proxy keys; an optional window-aware limiter adapter is also supported.
  JWKS publication is opt-in and asymmetric-only; key rings and redirect patterns are opt-in.
- There is no CLI and no built-in audit dashboard; React session hooks are available as an optional local package.

### Not planned

i18n and anomaly detection are explicitly out of scope. Features Signet does not have: phone OTP,
anonymous sessions, MCP, CIMD and DPoP. Captcha and compromised-password checks are shipped as
opt-in defensive controls. These are records of current scope, not promises of delivery.

The glossary terms email change, account deletion, fresh Session and trusted proxy describe
shipped capabilities; newer terms such as Session cache, Key ring and Redirect pattern describe
the opt-in hardening surfaces above.
