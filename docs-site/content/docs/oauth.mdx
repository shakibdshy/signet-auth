---
title: OAuth sign-in
description: Google and GitHub sign-in with PKCE and verified-only linking.
---

Register providers through `Config.OAuth` with a 32-byte `StateKey`, an
application origin and an exact redirect allowlist:

```go
cfg.OAuth = &signet.OAuthConfig{
    Providers: []signet.OAuthProvider{
        google.Provider{ClientID: id, ClientSecret: secret},
        github.Provider{ClientID: id, ClientSecret: secret},
    },
    RedirectBaseURL:  "https://api.example.com",
    AllowedRedirects: []string{"https://app.example.com/dashboard"},
    StateKey:         stateKey, // 32 bytes
}
```

Signet ships two provider adapters: [Google](/docs/google) and [GitHub](/docs/github). Each is a
small `OAuthProvider` implementation; you can add another provider without changing Signet
internals.

`POST /oauth/start` returns the provider authorization URL. `GET /oauth/callback`
redeems the code, consumes the encrypted single-use state, and redirects to the
allowlisted target with a new session cookie.

The sealed state contains the provider, redirect, verifier, nonce and expiry, is encrypted
with AES-GCM using `StateKey`, and expires after 10 minutes. It is stored as a single-use
Token digest and consumed on callback.

Signet requires PKCE, encrypts and expires the state, and only auto-links a
provider identity when its email is verified. An unverified identity yields a
one-time link token for explicit account linking via `LinkOAuthAccount`.

A provider Account owned by another User returns `ErrOAuthAccountConflict`; creation is
rolled back on failure. On a successful OAuth sign-in the redacted `OnSignIn` hook fires.
