---
title: Admin management
description: Guarded user management, role assignment and impersonation.
---

Admin actions are deliberately guarded: every state-changing operation checks a published
permission, requires a Session within `Accounts.FreshWindow`, and emits an `AuditEvent` for both
success and denial. Self-ban and self-delete are blocked.

## Configure it

```go
cfg.Authorizer = myAuthorizer       // grants the users:* and sessions:* permissions
cfg.RoleWriter = myRoleWriter       // required for AdminSetUserRole
cfg.AdminUserStore = myAdminStore   // implements ListUsersForAdmin
cfg.AuditSink = myAuditSink
cfg.Accounts = &signet.AccountConfig{FreshWindow: time.Hour}
```

The `AdminUserStore` interface has one method, `ListUsersForAdmin(context.Context) ([]*User, error)`.
Without an `AdminUserStore`, user listing is unavailable.

## List users and ban/unban

```go
users, err := auth.AdminListUsers(ctx, signet.AdminListUsersInput{ActorID: adminID})
err = auth.BanUser(ctx, signet.BanUserInput{ActorID: adminID, UserID: userID, Reason: "abuse"})
err = auth.UnbanUser(ctx, signet.UnbanUserInput{ActorID: adminID, UserID: userID})
```

Banning sets `User.Disabled` and revokes that User's Sessions. `AdminListUsers` returns `UserInfo`
values only — no password verifiers or secrets.

## Set roles

```go
err := auth.AdminSetUserRole(ctx, signet.AdminSetUserRoleInput{
    ActorID: adminID, UserID: userID, Roles: []string{"admin"},
})
```

Requires `PermissionUsersSetRole` and a `RoleWriter`.

## Revoke sessions

Session revocation uses the existing `RevokeSession`/`RevokeAllSessions` methods guarded by
`PermissionSessionsRevoke`.

## Impersonation

```go
started, err := auth.ImpersonateUser(ctx, signet.ImpersonateUserInput{
    ActorID: adminID, UserID: targetID,
})
// started.Token is the temporary credential; started.AdminID records the administrator.
err = auth.StopImpersonating(ctx, signet.StopImpersonatingInput{Token: started.Token})
```

Impersonation requires `PermissionUsersImpersonate`. It creates a short-lived signed credential
carrying the admin ID and the original session token; stopping invalidates the temporary credential
and restores the original Session. The temporary Session is revoked on stop. While impersonating,
admin checks use the administrator ID from the cookie, not the impersonated User. Self-impersonation
is blocked and the existing self-service deletion flow is disabled while impersonating.

Every impersonation start and stop emits an Audit event naming the administrator.

See [Authorization](/docs/authorization) and [Sessions](/docs/sessions).

The result type is AdminListUsersResult.

ImpersonationResult carries the temporary Token and AdminID.
