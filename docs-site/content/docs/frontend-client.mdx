The `@shakibdshy/signet-client` package is generated from Signet's OpenAPI contract, so the
methods and error codes match the server. You need **Node.js 20+**.

## Install

The package is not published to npm yet. Until it is, install it from a local checkout of this
repository:

```bash
cd /path/to/signet/client/ts
npm install
npm run build

cd /path/to/your-frontend
npm install /path/to/signet/client/ts
```

When a published version is available, this becomes `npm install @shakibdshy/signet-client`.

## Create the client

```ts
import { createSignetClient, SignetApiError } from '@shakibdshy/signet-client';

export const auth = createSignetClient({
  // Origin + your backend's Config.PathPrefix. If the Go server mounts
  // auth.Handler() at /auth, baseURL MUST include /auth.
  baseURL: 'https://api.example.com/auth',
});
```

<Callout title="Most common mistake">
Using only `https://api.example.com` as `baseURL` when the backend mounts Signet at `/auth`.
The generated client calls `/signup`, so without the prefix every request goes to
`https://api.example.com/signup` and returns 404.
</Callout>

Cookies are included automatically. The client fetches a CSRF token from `GET /csrf-token`,
caches it, and sends `X-CSRF-Token` on state-changing calls. You do not manage CSRF yourself.

## A complete login form

```tsx
import { useState } from 'react';
import { auth, SignetApiError } from './signet-client';

export function Login() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [error, setError] = useState('');
  const [user, setUser] = useState<{ email: string } | null>(null);
  const [challenge, setChallenge] = useState('');
  const [code, setCode] = useState('');

  async function submit(event: React.FormEvent) {
    event.preventDefault();
    setError('');
    try {
      const result = await auth.signIn({ email, password });
      if (result.two_factor_challenge) {
        setChallenge(result.two_factor_challenge);
        return;
      }
      setUser(result.user);
    } catch (err) {
      setError(err instanceof SignetApiError ? 'Invalid email or password.' : 'Something went wrong.');
    }
  }

  async function verifySecondFactor(event: React.FormEvent) {
    event.preventDefault();
    setError('');
    try {
      const result = await auth.verifyTwoFactor({ challenge, code });
      setUser(result.user);
    } catch (err) {
      setError(err instanceof SignetApiError ? 'Invalid or expired code.' : 'Something went wrong.');
    }
  }

  async function logout() {
    await auth.signOut({});
    setUser(null);
  }

  if (user) {
    return <div>Signed in as {user.email} <button onClick={logout}>Sign out</button></div>;
  }
  if (challenge) {
    return (
      <form onSubmit={verifySecondFactor}>
        <input value={code} onChange={e => setCode(e.target.value)} placeholder="Authenticator code" />
        <button type="submit">Verify</button>
        {error && <p role="alert">{error}</p>}
      </form>
    );
  }
  return (
    <form onSubmit={submit}>
      <input value={email} onChange={e => setEmail(e.target.value)} placeholder="Email" />
      <input type="password" value={password} onChange={e => setPassword(e.target.value)} />
      <button type="submit">Sign in</button>
      {error && <p role="alert">{error}</p>}
    </form>
  );
}
```

`signUp` works the same way. To render the signed-in User on page load, call the `/session`
endpoint or expose the User from your own server-rendered route; the client does not keep a
reactive session store.

## Passwordless sign-in

These endpoints are anonymous and CSRF-exempt.

```ts
await auth.sendMagicLink({
  email: 'ada@example.com',
  callback_url: 'https://app.example.com/welcome', // must be allowlisted on the server
});

// If your app owns the link route, exchange the token from the URL:
const sent = await auth.verifyMagicLink({
  token: new URL(location.href).searchParams.get('token')!,
  callback_url: 'https://app.example.com/welcome',
});

await auth.sendOtp({ email: 'grace@example.com' });
const result = await auth.verifyOtp({ email: 'grace@example.com', code: '123456' });
```

A normal clicked link navigates to `GET /verify-magic-link`, which sets cookies and redirects;
call `verifyMagicLink()` only when your frontend handles that route itself.

## Last sign-in method

When the backend enables [Last sign-in method](/docs/defensive-controls), the client can read the
signed cookie through the typed endpoint:

```ts
const { method } = await auth.lastSignInMethod();
// "password" | "username" | "magic-link" | "email-otp" | a provider name | ""
```

The value is empty when the feature is disabled, the cookie is absent or its signature is invalid.

## Second factor management

```ts
const enabled = await auth.enableTwoFactor({ password });
await auth.verifyTwoFactor({ challenge: enabled.challenge, code: '123456' });
const fresh = await auth.regenerateBackupCodes({ password });
await auth.disableTwoFactor({ password });
```

Enable, regenerate and disable are authenticated. Enrollment stays pending until the first
successful TOTP code; only then will `signIn` return a challenge.

## Handling errors

```ts
try {
  await auth.verifyOtp({ email, code });
} catch (err) {
  if (err instanceof SignetApiError) {
    switch (err.code) {
      case 'invalid_code':
      case 'invalid_link':
        return showMessage('That code or link is no longer valid. Request a new one.');
      case 'code_already_used':
      case 'link_already_used':
        return showMessage('You already used that proof. Request a new one.');
      case 'two_factor_required':
        return showMessage('Enter your authenticator code to continue.');
      case 'invalid_request':
        return showMessage('That sign-in link is not valid for this app.');
      case 'rate_limited':
        return showMessage('Too many attempts. Try again shortly.');
    }
  }
  throw err;
}
```

All codes are listed in [Errors](/docs/errors); request and response shapes come from the
generated [OpenAPI contract](/docs/openapi). Server setup lives in [Passwordless sign-in](/docs/passwordless),
[Second factor](/docs/two-factor) and [Username and accounts](/docs/accounts).

## Separate backend repository

The backend team can merge this base spec into its own application spec and publish a versioned
SDK. The frontend then depends on that SDK; a breaking server shape change becomes a major
version and fails the build at the affected call sites. See [HTTP API](/docs/http-api).
