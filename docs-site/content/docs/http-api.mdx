title: HTTP API
description: All 13 endpoints, their authentication and CSRF requirements, and when to use each.
---

`Client.Handler()` returns a standard `http.Handler`. Mount it under `Config.PathPrefix`
(default `/`) — the example apps mount it at `/auth`:

```go
mux.Handle("/auth/", http.StripPrefix("/auth", auth.Handler()))
```

Every path below is relative to that prefix, so with the example it becomes
`/auth/signup`, `/auth/signin`, and so on. Request and response JSON shapes are generated
from the declarative contract into the [API reference](/docs/openapi).

## Endpoint map

| Method + path | Auth | CSRF | Success | Use it when |
| --- | --- | --- | --- | --- |
| POST `/signup` | no | exempt | 201 `{"user":User}` | Creating a User and its credential Account. |
| POST `/signin` | no | exempt | 200 `{"user","session_token","csrf_token"}` | Exchanging credentials for a Session; sets cookies and returns the CSRF token. |
| POST `/signout` | no | required | 204 | Ending the current Session and clearing its cookie. |
| GET `/sessions` | yes | n/a | 200 `{"sessions":[SessionInfo]}` | Listing the authenticated User's Sessions. |
| DELETE `/sessions` | yes | required | 204 | Revoking all Sessions of the authenticated User. |
| DELETE `/session` | yes | required | 204 | Revoking just the current Session. |
| POST `/token` | no | exempt | 200 `TokenPair` | Exchanging credentials or a Refresh token when JWT is enabled. |
| POST `/send-verification` | no | required | 200 | Issuing a fresh email-verification Token. |
| POST `/verify-email` | no | required | 200 | Consuming the verification Token from the emailed link. |
| POST `/send-password-reset` | no | required | 200 | Requesting a password-reset Token. |
| POST `/reset-password` | no | required | 200 | Consuming the reset Token and setting a new password. |
| POST `/oauth/start` | no | exempt | 200 `{"url":...}` | Starting an OAuth flow; returns the provider authorization URL. |
| GET `/oauth/callback` | no | exempt | 302 | Provider redirect target; sets a Session cookie or appends a `link_token`. |
| GET `/csrf-token` | no | exempt | 200 `{"token":...}` | Obtaining a CSRF token for browser requests; sets the CSRF cookie. |

Anonymous endpoints are exempt from the CSRF guard. State-changing requests that carry a
session cookie must present `X-CSRF-Token`; see [Sessions and cookies](/docs/sessions).

## Errors

Failures return `{"error": code, "message": msg}` with the status codes listed in
[Errors](/docs/errors). Common ones: `invalid_credentials` 401, `email_not_verified` 403,
`invalid_token` 401, `rate_limited` 429, `csrf` 403.

## Request bodies

Request structs are aliased from the private domain types and carry JSON tags. Fields
named `RateLimitKey` are `json:"-"` — the server derives them from the connection address,
so a client cannot override its rate-limit key. `TokenInput` accepts either
`email` + `password` or `refresh_token`.

## Generated reference

Each operation has a generated page with schemas, response samples and example code under
`/docs/openapi/...`. Those pages are produced from `api/signet.openapi.json`; never edit
them by hand. See [Tooling](/docs/tooling) for regeneration.
