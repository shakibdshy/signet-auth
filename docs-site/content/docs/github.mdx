---
title: GitHub sign-in
description: Configure the GitHub OAuth provider adapter.
---

The `oauth/github` adapter implements Signet's public `OAuthProvider` interface. It uses PKCE,
requests the `user:email` scope, and reads the User ID from `/user` plus the primary email from
`/user/emails`.

```go
import (
    "github.com/shakibdshy/signet"
    "github.com/shakibdshy/signet/oauth/github"
)

cfg.OAuth = &signet.OAuthConfig{
    Providers: []signet.OAuthProvider{
        github.Provider{
            ClientID:     os.Getenv("GITHUB_CLIENT_ID"),
            ClientSecret: os.Getenv("GITHUB_CLIENT_SECRET"),
        },
    },
    RedirectBaseURL:  "https://api.example.com",
    AllowedRedirects: []string{"https://app.example.com/dashboard"},
    StateKey:         stateKey, // exactly 32 random bytes
}
```

Register `https://api.example.com/auth/oauth/callback` as the OAuth callback URL with GitHub
(adjust for your `PathPrefix`).

## Identity details

- Provider name stored on the Account: `github`.
- Provider user ID: GitHub's numeric user ID, stored as a string.
- Email and verification flag come from the primary entry in `/user/emails`; a primary but
  unverified address is not auto-linked.

Signet auto-links a provider identity only when the email is verified. An unverified identity
yields a single-use link Token for explicit linking through `LinkOAuthAccount`.

## Endpoints

`AuthEndpoint`, `TokenURL`, `UserInfoURL` and `EmailsURL` override the defaults. They exist for
tests; leave them empty in production.

See [OAuth sign-in](/docs/oauth) for the shared `/oauth/start` and `/oauth/callback` flow, state
encryption and redirect rules.
