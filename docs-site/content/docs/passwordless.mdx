---
title: Passwordless sign-in
description: Magic links and six-digit email OTPs as alternatives to password sign-in.
---

Magic links and email OTPs are additional first factors: passwords keep working exactly as
before. Both prove control of an email address, mark it verified, and create a Session. A User
created this way has no credential Account until they set a password.

Configure them with `Config.Passwordless` (`PasswordlessConfig`). `DefaultConfig()` sets
`MagicLinkTTL` and `OTPTTL` to five minutes. `AllowSignUp` is a `*bool`: nil means true, and an
explicit `false` turns off auto-creation. `AllowedRedirects` is checked first, then the OAuth
allowlist, then the `AppURL` origin.

```go
allowSignUps := true
cfg.Passwordless = &signet.PasswordlessConfig{
    MagicLinkTTL: 5 * time.Minute,
    OTPTTL:       5 * time.Minute,
    AllowSignUp:  &allowSignUps, // a *bool; nil also means true
    AllowedRedirects: []string{"https://app.example.com/welcome"},
}
```

<Callout title="Send limits are your responsibility">
`RateLimitRule` carries a limiter and key prefix, not a window. Configure 5 requests/minute for
`send-magic-link` and 3/minute for `send-otp` in your own limiter. Failed OTP guesses are
throttled separately through `verify-otp` using the email and client IP as the key.
</Callout>

## Go API

| Method | Purpose |
| --- | --- |
| `SendMagicLink(ctx, SendMagicLinkInput) error` | Email a single-use link. `CallbackURL` is embedded in the proof and must be allowlisted. |
| `VerifyMagicLink(ctx, VerifyMagicLinkInput) (*SignInResult, error)` | Consume the token, mark the email verified, create a Session. |
| `SendEmailOTP(ctx, SendEmailOTPInput) error` | Email a six-digit code. |
| `VerifyEmailOTP(ctx, VerifyEmailOTPInput) (*SignInResult, error)` | Submit `Email` and `Code`; consume the proof and create a Session. |

```go
// Existing user
err := auth.SendMagicLink(ctx, signet.SendMagicLinkInput{
    Email: "ada@example.com",
    CallbackURL: "https://app.example.com/welcome",
})
result, err := auth.VerifyMagicLink(ctx, signet.VerifyMagicLinkInput{Token: tokenFromEmail})

// New or existing user
err = auth.SendEmailOTP(ctx, signet.SendEmailOTPInput{Email: "grace@example.com"})
result, err = auth.VerifyEmailOTP(ctx, signet.VerifyEmailOTPInput{
    Email: "grace@example.com", Code: "123456",
})
```

`SendMagicLinkInput`, `VerifyMagicLinkInput`, `SendEmailOTPInput` and `VerifyEmailOTPInput` are
the public input types. Both verification methods return `SignInResult` with `User` and raw
`SessionToken`.

## HTTP API

| Endpoint | Method | Auth | Purpose |
| --- | --- | --- | --- |
| `send-magic-link` | POST | anonymous | Sends the link email. |
| `verify-magic-link` | GET | anonymous | Consumes `token`, sets cookies, then redirects to `callback_url` or returns session JSON. |
| `send-otp` | POST | anonymous | Sends the six-digit code. |
| `verify-otp` | POST | anonymous | Exchanges `email` and `code` for a session cookie and JSON. |

All four are CSRF-exempt anonymous endpoints, as `signin` is. No `user_id` is sent in request
bodies.

## Proofs and storage

`TokenMagicLink` and `TokenEmailOTP` are the two new `TokenKind` values, both included in
`AllTokenKinds` and therefore in every revocation sweep. A magic-link proof is issued through
`IssueWithData`; its embedded email and callback are covered by the stored digest. An OTP is
written directly: the stored `Hash` is `Digest(email + ":" + code)`, so the raw code is never
persisted. Resending rotates the proof by deleting the previous Token for the same subject.
Expired or replayed proofs return `ErrTokenInvalid` or `ErrTokenExpired`.

## Custom email templates

Adding methods to `EmailTemplates` would break custom implementations, so the two new templates
are optional interfaces: `MagicLinkTemplates` has `MagicLink(TemplateData) Message` and
`EmailOTPTemplates` has `EmailOTP(TemplateData) Message`. `TemplateData.Code` carries the OTP.
`DefaultTemplates` implements both; a custom `EmailTemplates` that does not still gets the
built-in messages.
